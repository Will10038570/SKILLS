# 模組流程檢查

分析**指定模組**，說明其作法與流程——聚焦在**發生什麼事、怎麼用**，而非程式碼怎麼寫。

目標模組（來自使用者）：$ARGUMENTS

## 調查方式

1. **確認模組邊界。** 若 $ARGUMENTS 空白或不明確，詢問使用者：想了解哪個模組、套件、目錄或元件。不猜測。
2. **找到進入點。** 尋找 `main` 函式、持有頂層邏輯的 class、啟動此模組的 launch file 或 config，或公開的 CLI entry。
3. **理解整體策略。** 此模組用什麼方式解決問題？有什麼核心機制？
4. **追蹤執行流程。** 從進入點到結束，各步驟做什麼事、用哪支檔案、會讀寫哪些外部資源（檔案、資料庫、API）。
5. **蒐集可用參數。** CLI flag、config key、constructor arg——名稱、預設值、控制什麼。

## 輸出格式

標題：**[模組名稱] 做法與流程**

以下四個部分，依模組性質選用適合的呈現方式：

### 策略概覽
1–3 句說明核心想法，可附 ASCII 流程圖說明資料流向：

```
輸入 → 處理 A → 處理 B → 輸出
```

### 關鍵機制
若模組有需要說明的核心元件（例如量測方式、量化策略、資料結構），以 ASCII 表格呈現：

```
┌──────────┬────────────────────────┬────────────────┐
│   欄位   │          說明          │      備注      │
├──────────┼────────────────────────┼────────────────┤
│  指標 A  │ 量法描述               │ 為什麼這樣量   │
└──────────┴────────────────────────┴────────────────┘
```

### 執行流程
若模組是多步驟的執行程序，以編號步驟呈現，每步附指令與簡短說明：

```
Step 1：做什麼

python some_script.py [參數]
一句話說明這步做什麼、輸出到哪裡、有哪些可調參數。

---
Step 2：做什麼
...
```

若模組是單一工具或 class，直接描述呼叫方式與行為即可，不必強拆成步驟。

### 可用參數
以 ASCII 表格列出（若參數很少，inline 說明也可）：

```
┌────────────┬──────────┬──────────────────────────┐
│    參數    │   預設   │          說明            │
├────────────┼──────────┼──────────────────────────┤
│ --flag N   │ 3        │ 控制什麼                 │
└────────────┴──────────┴──────────────────────────┘
```

預設值必須來自實際讀到的程式碼（附 file:line）；找不到則寫「不確定」。

## 規則

- **唯讀。** 不建立、編輯或刪除任何檔案。不執行 build、test 或任何會改變狀態的指令。
- **正確性優先於完整性。絕不猜測。** 參數名稱、預設值、行為描述必須來自實際讀到的內容；附 `file_path:line`。無法確認則寫「不確定」。
- **不解釋程式碼。** 不逐函式、不逐行走過。提到檔案只為了說明哪一步在此處理。
- **精簡。** 每個步驟一段話就夠，不要展開成子條列、子表格。如果某個部分對讀者沒有資訊量，就省略。
- **以繁體中文（zh-TW）回應。** 模組名稱、檔案名稱、型態名稱、方法名稱、參數名稱及技術術語保留英文原文。
